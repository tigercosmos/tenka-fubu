# M6 外交與家臣實作裁決

本階段把外交、朝廷、調略及家臣生命週期接入既有每日流程。以下裁決補足文件間的缺口，
不改動十三步順序，也不讓畫面直接修改模擬狀態。

## 歷史初始化與官位

劇本保留歷史官位與役職。02 與 s1560 資料指定足利將軍家，優先於 08-T1 的全員無官位描述。
`src/data/courtMetadata.ts` 依劇本 ID 提供朝廷所在地與將軍家，不在敘任驗證器硬編二條城。
將軍不是五階可敘任役職的第六階；幕府滅亡清除將軍名義，但不回收未曾授予的役職威信。

官位解鎖向上累計。從四位上的政策槽與正二位的第二槽可並存，管領另增一槽。
官位保留於勢力，不隨當主更替消失。13 歲一門可結婚，但未元服者不可執行外交工作。

## 和平與進行中的戰鬥

協定於接受時再次驗證前置與資源。費用不足的失敗不扣款，也不新增拒絕冷卻。
援軍請求使用 09 援助分，不使用一般接受度公式；接受只發事件，派兵屬 M7。

外交步驟在軍事步驟前停止協定保護的圍城與制壓。若野戰兩側任一勢力對成立和平，
整場野戰停止，部隊嘗試歸還；不判勝敗，也不給士氣、威信或追擊獎勵。
這項保守裁決避免多勢力混合部隊的聚合傷害誤傷受協定保護者。
後續加入與組成聯軍時，必須對所有對側勢力交戰。海路也不得繞過停戰通行限制。

從屬上繳以當月實際金錢收入計算。先結算各家收入，再轉移上繳，最後扣薪俸與政策費。
上繳不以庫存或收到的上繳再計算，亦不因勢力 ID 排序改變支付能力。

## 內應、捕虜與具申

存檔 v2 保存內應原對象與城級免疫。換將及易主的寫入邊界立即清除成功標記，
避免同日換回原城主後重新使用舊成果。每日與發動前另作檢查，期限最後一日仍有效。

武將轉籍、死亡、捕獲與出奔共用役職清理。仍存續的原家捕虜獲釋後回到原家城池；
原家已滅亡者成為浪人。06 提到釋放與處決的外交感情效果，但 08 沒有對應數值；
本階段不推測該數值，另向使用者確認。

具申的內含 Command 必須屬同一家，且不可再次解析具申。採納先驗證，再執行一次及給獎勵。
已完成具申於下一個月初清除；此期限隨存檔保存。
採納與拒絕另保存武將的 60 日再提案冷卻；逾期或失效不啟動此冷卻。
釋放捕虜的威信獎勵仍受 `BAL.prestigeMax` 上限約束。

## 暫停與家臣操作

畫面選擇仍排入 Command 佇列，於下一 tick 執行。畫面暫時隱藏已排入的決策，
只在該互動擁有暫停時恢復速度；手動暫停不因新來使、具申或月初事件而被接管。
硬驗證拒絕後，仍待回覆的來使重新顯示。換局清除上一局的畫面決策記錄。

11 家臣詳情的「移動」草圖沒有 06 行為規則或 02 Command 契約。本階段不建立直接改狀態的按鈕；
提供已定義的褒賞、任城主、封知行、登用與捕虜操作。毀約與處決的確認採原生焦點按鈕語意，
Enter 不得在焦點位於取消時執行處決。

## 無視窗流程驗證

Playwright 一律使用 headless，HTML 報告不自動開啟。除錯 API 的 `startM6Flow()`
只建立新的 s1560 織田局，複製初始狀態後設定測試前置，不修改既有遊戲。
固定種子 5 由實際調略解算搜尋取得；不替換亂數，也不預先製造成功結果。

現有正式資料只有東海與畿內，尚無甲斐武田家。測試補入的武田家、信玄與躑躅崎館
明確標為 synthetic debug fixture；座標與數值是測試模板，不是歷史資料。
此流程驗證外交操作與結算，不代表 M8 全國資料已完成，也不代表 M7 援軍派兵已完成。

## 決定論快照變動

新城池欄位、存檔版本、月結算及生命週期接線會改變狀態 hash，故重算既有 miniature、
軍事 replay 與合戰 transcript 的實測快照。新增五年外交腳本另保存 60 個月度 hash。
最後新增 `proposalCooldownDays` 常數後，只更新五份檔案的 BAL hash 為
`26f8938846912a86`；22 個邊界、golden 與 replay 測試確認原有狀態 checkpoint 不變。
未放寬 replay 斷言、截圖差異或效能門檻。
