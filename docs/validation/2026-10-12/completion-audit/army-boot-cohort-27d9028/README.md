# Army-plate boot under the first-wave native cohort

The three army-plate geometry cases in the original `9550e397` 440-case run timed out during their unchanged five-second `waitMapIdle` poll. A single read-only derivative at `27d9028f01e38e67cfb0adf65b933ffd44485930` reproduced two of those boot failures with a selected 18-case cohort. The Sunpu/Narumi case passed. No product fix or timing allowance was changed.

The cohort contains the exact 18 test identities that began in the original first wave: five army-plate tests (two pure oracles and three geometry cases), three actor-depth, two ai-corps, two accessibility, and one each of army DOM selection, auto-return, annotation, orders, operational readability, and cloth material. The current one-shot error-control test was excluded because it was not a historical peer. The derivative ran with `CI=1`, `VISUAL_GPU=1`, Chromium, 16 workers, the original 60-second case and 300-second global deadlines, and the original geometry assertions. Its banner says **18 tests using 16 workers**; the report records 16 passed, two failed, zero skipped in 31.65 seconds. All 16 long-running cases were active when each failed page entered its browser-side callback. Selected-test scheduling remains distinct from the original full suite.

Each Playwright trace shows an outstanding evaluate API before the corresponding browser callback record. The callback then waited at the documented renderer idle gate while art remained pending. Ticker heartbeats continued, so these two reproduced failures were neither an absent renderer nor a stopped ticker. Generation numbers and renderer instance IDs distinguish active completion from stale `finally` callbacks. The table shows Playwright trace timing reconstructed from its recorded wall/monotonic origin, browser `performance.timeOrigin + performance.now()`, and Node console receipt separately. Their approximate UTC correlation helps sequence events but does not establish a precise cross-process interval or prove that IPC caused the delay. The dense callback's **Node receipt** followed the poll failure in the retained trace.

Both failed pages recorded 29 PNG requests with HTTP 200. The latest recorded network-resource end was about 13:38:38.8, before either poll deadline. Network receipt does not establish bitmap decode, Pixi texture creation, or terrain/castle attachment completion. The observed proximal blocker is the art-pending idle gate; time before the browser callback was observed may also contribute. The exact post-receipt cost remains unmeasured. The previous [Blob transport controls](../blob-worker-transport-sim2/README.md) rule out casually restoring Pixi image workers: Blob-only controls failed near wave 40, ArrayBuffer-only skipped decoding, and ArrayBuffer-to-bitmap was unreliable. The `preferWorkers: false` production policy was unchanged.

The temporary observer is fully named in [its overlay manifest](raw/review-manifest-v3.json.gz) and [diff](raw/review-v3.patch.gz). It adds browser callback, renderer registration, art-pending transition, ticker heartbeat, and idle-waiter timestamps only to the three affected pages. Unmarked peer pages retain their original waiter resolve function and create no diagnostic snapshots. The added branch and logs can still perturb timing, so this is not an exact uninstrumented replay. Source/dependency proofs before, after build, and after the run match all 1,650 scoped Git inputs except the three declared modified overlays, the one declared new helper, and all 29 pinned Pixi files. The build and typecheck passed. `VISUAL_GPU=1` selected the Linux Vulkan launch flags, but this observer did not read same-page GL identity.
