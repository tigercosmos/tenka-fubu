# Actor depth projection oracle — `1464146`

The original native actor-depth case compared castle body scene Y against an unprojected game-state Y. In the Sunpu camera, elevated Gifu was 2768.4 in the rendered scene while its canonical Y was 2774. The retained original three-case run on the unchanged `8ea965a` runtime had one failure at that assertion and two passes. This was an invalid test oracle: `MapRenderer.presentPoint()` projects castle positions using sampled terrain elevation before the castle node copies its position to the shared actor body layer.

Commit `146414688dc2ceceb81042aeed6984ddf0687926` changes only `e2e/actor-depth-layout.spec.ts`. For each visible castle, the test now links its independent elevation-node observation to the canonical game position, checks bounded height and the published `x − 0.18 × height` projection relation, and compares body foot Y **exactly** to that independently observed projected scene Y. The Sunpu camera must include a visible lifted castle, so reverting to the old canonical-Y oracle cannot silently pass. The army-anchor derivation also starts at the projected reference castle Y. World-foot ordering, body-frame overlap, selection behavior, and the other two original cases remain asserted.
