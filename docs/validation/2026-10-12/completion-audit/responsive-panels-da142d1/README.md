# Diplomacy, Corps, and Taimei responsive endpoint controls — `da142d1`

On isolated `da142d148c7a3833ec9dc970659643ed62df6dc0`, nine native Chromium cases passed at 1280×720: each of the Diplomacy, Corps, and Taimei panels at UI scales 0.8, 1.0, and 1.5. These are **endpoint controls**, not the final 15-scale matrix or an M8-23 completion claim. The later four-step new-game wizard is outside this source pin; the test used the original scenario/clan two-step wizard after the title-screen new-game action. No product source, gate threshold, or baseline changed in this control.

| Panel     | Passed cases | Tested behavior                                                                                                                                                            |
| --------- | -----------: | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Diplomacy |          3/3 | F3 keyboard entry, all three tabs by arrow key, first/last clan selection, aid-target selection, six proposal controls, court/shogunate action and final table text, close |
| Corps     |          3/3 | F6 keyboard entry, new-corps editor, leader/advance target, three directives, first/last owned-castle rows, create action, close                                           |
| Taimei    |          3/3 | F7 keyboard entry, all eight cards and their selected detail heading, invoke action, close                                                                                 |

Each tested control was scrolled into view and measured against its viewport and scroll/clip ancestors. Measured action surfaces had at least 32 physical and visible pixels in both dimensions. Heading/card/table text used DOM Range rectangles within its text host; document width remained 1280px. The test exercised the real Settings slider and panel hotkeys. Diplomacy's same-page WebGL read in all three cases reported `Google Inc. (NVIDIA)` and `ANGLE (NVIDIA, Vulkan 1.4.312 ... RTX 5070 Ti ...)`. The launcher explicitly set `VISUAL_GPU=1` with the sim2 Chromium binary; the panel tests themselves validate DOM behavior and do not measure FPS or GPU timing. Screenshots were visually inspected at scale 1.5. They show the selected, scrolled content, so they are not pristine initial-panel captures or proof that every line of panel text is readable. Enabled Corps/Taimei commands were not submitted; this package covers UI reachability, not command settlement.

The first Diplomacy run was RED because the new test attempted to find initial keyboard tab entry _after_ changing a combobox. Moving that observer to immediately after F3 yielded the 3/3 control. Two Taimei runs were RED from test selectors: the first counted a ninth pressed button outside the eight cards; the next supplied a `has` locator rooted at the panel rather than the candidate card. `button[aria-pressed]:has(strong)` yielded the final 3/3 control. These are retained test-observer failures, not demonstrated product defects. Their reports and process logs are in `raw/*-red-*/`. Exact test bytes are retained for the final Diplomacy control (`original-diplomacy-test.spec.ts.gz`, SHA-256 `ddefd52c…`) and the final three-panel control (`original-three-panel-test.spec.ts.gz`, SHA-256 `6c929cb1…`); the intermediate RED overlays and Corps-only overlay were overwritten on the isolated host, so those reports preserve their failing source snippets but cannot establish complete overlay-byte identity.

The runtime was prepared from a scoped Git archive/manifest of 1,633 tracked inputs. Its `node_modules` was a reused, explicitly pinned cohort with 29 patched Pixi targets, **not** a fresh install this tranche. Before and after the controls, the source/dependency verifier reported zero mismatches; see `raw/tenka-da-responsive-source-*.json.gz` and `source-manifest.json.gz`. The untracked test overlay and launcher were checked separately. All six native runs have unique remote directories; pass metadata, raw reports/logs, and nine successful screenshots are copied here. The full RED traces remain on sim2 at `/tmp/tenka-da-responsive-control-c1`, `/tmp/tenka-da-responsive-control-taimei-c4`, and `/tmp/tenka-da-responsive-control-taimei-c5`, without local trace copies.
