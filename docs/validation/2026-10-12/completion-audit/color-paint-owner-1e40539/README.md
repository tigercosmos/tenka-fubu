# Color-vision screenshot paint-owner diagnosis

The unchanged achromatopsia test remains RED on the frozen `1649c65` runtime plus the final earned-alliance test overlay: Chromium CDP restored `none`, but the full-page screenshot had **9** changed RGBA pixels (expected 0). The changes were at x=1120/1215/1225, y=16/17/46/47, along HUD command edges. The old `8ea965a` isolated failure had 416 changed pixels at x=10–69, y=14–63, between the HUD and left rail. These are different observations; neither establishes a game-map rendering defect.

The test captures `page.screenshot()` for the entire 1280×720 page (`e2e/color-vision-map.spec.ts:114–141`). Its `canvas` record is only a DOM rectangle. `MainScreen.tsx:1287–1306,1388–1390` places the Pixi map below HTML HUD and rail. `MainScreen.module.css:7–20,96–113` gives those elements `--shadow-1`; `tokens.ts:73,84–87` defines the shadow and map/HUD z-order. The test's exact-restoration check therefore covers HTML compositing as well as Pixi map paint. Its failure occurs before the subsequent state/diagnostic assertions, although the preserved original pre/post observations independently match for state, command log, and canvas rectangle; only ticker timing differs.

One **temporary test-only** diagnostic used the same frozen runtime and achromatopsia mode. It compared full-page no-CDP and CDP/restored pairs with normal HTML, then with only HUD/rail shadows disabled, then with HUD/rail hidden. The three no-CDP pairs were identical. The emulated frames changed all 921,600 pixels, confirming the CDP mode took effect. Restoration differed by 11 pixels with normal HTML, 6 with shadows disabled, and 0 with HUD/rail hidden. All 11 and 6 differences were at x=1120–1225, y=16–47; none was at the old left seam. HUD/rail layout rectangles remained x=12,y=8,w=1256,h=48 and x=8,y=64,w=64,h=644; the canvas rectangle remained 0,0,1280,720 and state version stayed 0. Disabling shadows does **not** remove all differences, so shadows alone are not the cause. Hiding HUD/rail removes the observed residual in this run, implicating HTML/compositor paint, but it does not prove Chromium's internal cause or exclude a separate old seam cause.

The diagnostic also recorded `canvas.toDataURL()` at each stage. Every raw 1280×720 image sampled as one black color; it is invalid as map-pixel evidence, consistent with a cleared WebGL drawing buffer between renders. No canvas-pixel equality claim is based on it. The original test's preserved `overview-none.png` and `overview-restored.png` provide the independent 9-pixel RED. No pixel threshold, baseline, product CSS, or test assertion was changed.

`plan/17-testing.md:515–537` requires fixed three-camera visual baselines with controlled diff policy and manual color-vision/grayscale inspection of enemy/friendly, warning/hostile, and road shape cues. The next bounded investigation should normalize the compositor/emulation paint **before** each baseline and restored capture, then retain exact equality and the original state/diagnostic assertions. This is a proposal, not a validation result or a change to acceptance policy.
