# Map renderer startup readiness (`c74a46c`)

The frozen `1464146` native suite reported renderer-not-mounted errors in `army-plate-material` and `context-panel-focus`. The first called `setMapCameraPreset`, and the second called `waitMapIdle`, immediately after observing the strategy screen. Both debug methods require the renderer registered by `MapCanvasHost` after font loading and asynchronous initialization. The earlier [coast readiness control](../coast-readiness-diagnosis-8ea/README.md) showed that strategy DOM visibility does not prove registration.

Commit `c74a46c83a3db3dea703196781c4c85c9f02bf5c` moves coast's ready check to `e2e/map-ready.ts` and calls it before the **first** map debug action in these two affected cases. The helper polls the existing `getMapDiagnostics().ready` and treats only the documented not-mounted exception as transient. Other exceptions still fail. It is not a global fixture hook. The coast delayed-registration test still checks that the helper remains pending until the renderer registers. All original army material, context focus, and coast assertions remain; configured case/global limits and the 5-second expectation limit are unchanged. No product source, debug contract, rule, or protected baseline changed.
