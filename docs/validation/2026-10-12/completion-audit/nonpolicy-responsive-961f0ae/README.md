# M8-23 non-policy responsive acceptance (frozen `961f0ae`)

At native 1280×720, the OfficerList, Settings, and Save/Load panels passed all 15 supported `uiScale` values (0.8–1.5 in 0.05 steps): **45/45 Chromium cases passed**. This covers three panels, not every M8-23 screen. The product source was frozen at `961f0ae`; the new acceptance test is commit `cf9fb7e`.

The test follows [11 §3.16.2](../../../../../plan/11-ui-screens.md), [11 D24](../../../../../plan/11-ui-screens.md), and [11 D26](../../../../../plan/11-ui-screens.md): viewport-constrained scrollable panels, no document horizontal overflow, at least 32×32 CSS px physical actions, and an unobstructed OfficerList recruitment control at 1.5. It starts a real Oda 1560 game through the title UI for each case, sets the scale with the settings slider, and uses native headless Chromium on isolated Linux `sim2`.

The OfficerList case reaches the last officer vertically, scrolls its table horizontally when needed to reach the rightmost role cell, checks the recruit/reward controls and their Tab order, and opens the last officer detail with Enter. Settings reaches reset, opens its confirmation with Enter, cancels, and returns. Save/Load reaches the last manual slot, writes a save with Enter, switches to Load, and checks that the saved slot and import control are reachable. Across these panels the measured minimum control width and height were 32 px; OfficerList row height was at least 32 px. The reporter, per-case geometry JSON, process metadata, and exact stdout/stderr are in [raw-final-runs.tar.gz](raw-final-runs.tar.gz). Source proof covered 1,631 tracked files with zero Git-blob mismatches before and after; dependency proof covered 29 installed Pixi patch targets with zero mismatches and identical inventories before and after. The E2E file SHA-256 was `35f878b6bec964e5211cea35251389432bb5f7fc19cefcb61ac8aaf0bf081255` on both machines.

Endpoint screenshots were inspected at the scroll position needed to reach the tested controls. At 1.5, clipped top or left table content in a screenshot is intentional internal scrolling; the test reaches both the left name and right role cells. These screenshots support endpoint visual review, while the geometry and action assertions cover the 15-step matrix. They do not prove a minimum font size or every label's text readability. The Load case checks a saved slot's enabled state but does not execute a load or import.
