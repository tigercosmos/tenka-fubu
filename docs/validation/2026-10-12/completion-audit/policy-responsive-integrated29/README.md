# Integrated Linux policy responsiveness and target sizes

The policy portion of M8-23 / 11-T8 passes in native headless Chromium at the minimum supported 1280×720 viewport with every supported `uiScale` value, 0.8–1.5 in 0.05 steps. This run combines the adopted policy test from `7d37c28` with the 29-target Pixi dependency recipe. All 15 cases passed, covering 180 visits to the 12 policy cards, their details, scrolling, visible actions, and keyboard entry/navigation. A separate probe passed at all 15 scales and measured 375 rendered policy targets against the 32×32px lower bound in [11-D24](../../../../../plan/11-ui-screens.md).

The isolated sim2 runner was `/tmp/tenka-policy-responsive-d7c0337`. Its original 1,545-file d7c0337 source inventory had zero mismatches immediately before the [three-file integration overlay](overlay.tar.gz); the [preservation proof](baseline25-preservation.json.gz) and [original inventory](d7-tracked-inputs.json.gz) are retained. The overlay changed the Pixi recipe and dependency-patch test and added the texture batch-ID test. The adopted policy test was already overlaid onto the d7 runner. The [integrated input inventory](integrated-manifest.json.gz) contains 1,557 paths, including root configuration files omitted from the earlier inventory. [Source verification before](source-before.json.gz) and [after](source-after.json.gz) the first run found zero mismatches; [recovery verification](recovery-verification.json.gz) again found zero mismatches after the last run. The policy test and Pixi recipe SHA-256 values match `7d37c28`: `87055d92ecca106c7a17c587ea2dd23da18949c4c00da421aa7a6398a886aa86` and `aef14f315cea70876118b659b247b0b7556e5c9d8da233716c6307364f7c3bef`. The [overlay input hashes](overlay-inputs.sha256) identify the transferred files.

A fresh locked [npm install](npm-ci.log.gz) and [build](build.log.gz) exited 0. All [29 installed Pixi targets before](runtime-pixi29-before.json.gz) and [after](runtime-pixi29-after.json.gz) the native runs matched their pinned patched hashes. The host reported [NVIDIA GeForce RTX 5070 Ti, driver 580.178.04](gpu.txt). This records the host GPU identity; the policy assertions themselves inspect DOM layout and do not establish WebGL rendering quality.

The first integrated [native policy run](policy-native29.log.gz) passed 15/15 in 1.2 minutes, but its default Playwright `test-results` directory was overwritten when the separate target-size probe began. Its log and source/dependency proofs remain; its geometry rows and screenshots do not. The target-size probe's [log](target-size-probe.log.gz), [script](policy-target-size.probe.spec.ts.gz), and [raw output](target-size-results.tar.gz) were frozen before the next run. It passed 15/15 in 1.1 minutes. Across 15 close buttons, 180 card-open buttons, and 180 detail actions, the minimum rendered boxes were respectively 32×32, 292.5625×33.96875, and 48.390625×33.96875 CSS px. The probe did not test every other UI control or prove the full M8-23 gate.

A separately labeled **recovery run** used a unique `--output` path and [JSON reporter](policy-native29-recovery.report.json.gz). It passed 15/15 with zero unexpected, skipped, or flaky cases from [07:07:17 to 07:08:31 UTC](policy-native29-recovery.started-utc). Its [raw results](policy-native29-recovery-results.tar.gz) preserve 15 geometry files, 15 keyboard-entry traces, 15 reverse-focus traces, and these exact three screenshots: [0.8](policy-responsive-0.8.png), [1.0](policy-responsive-1.png), [1.5](policy-responsive-1.5.png). [Verification](recovery-verification.json.gz) counted 180 geometry rows and three PNGs. Visual inspection found the policy detail action and close control visible at all three endpoints; the 1.5 minimap covers only the lower-right blank panel area in the captured view. The recovery images belong to this second run, not the first integrated run.

The earlier d7 baseline [evidence package](../policy-responsive-d7c0337/README.md) discloses an initial `npm ci` command with an incomplete Node `PATH`, exit 127, whose raw output was overwritten before preservation. That missing raw output was not reconstructed here. This package also records the avoidable first integrated-run artifact overwrite above. Future native runs should set a unique `--output` directory and unique reporter/log files for each invocation and preserve the complete directory before starting another suite. Raw logs and executable probe source are gzip-compressed to keep their original bytes. No protected reference, visual threshold, plan, balance constant, or product source was modified for these checks.
