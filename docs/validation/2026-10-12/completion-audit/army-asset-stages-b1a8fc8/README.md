# Army-plate boot asset stages under the selected native cohort

At `b1a8fc8b21119bc3e540a6d5c5a83f1bd9911353`, one guarded, read-only derivative of the earlier [18-case cohort](../army-boot-cohort-27d9028/README.md) reproduced the original five-second army-plate boot poll failure in all three geometry cases. Fourteen tests passed and four failed in 32.42 seconds; the fourth failure was an independent accessibility case whose map renderer was not mounted. No geometry assertion in the three army-plate cases executed after its failed boot poll. This selected cohort is not a replay of the full 440-case `9550e39` schedule, and the diagnostic wrappers can perturb timing.

The asset chain is concrete. `MapRenderer.loadTerrainTextures` waits for seven groups of `MapAssetLoader.acquire` calls, then builds and attaches terrain before clearing `terrainTexturesPending`. `loadCastleBodyArt` waits for four castle textures, calls `setBodyArt` on castle parts, then clears `castleArtPending`. `MapAssetLoader.loadResource` awaits Pixi `Assets.load`. With the existing `preferWorkers: false` policy, the installed Pixi texture parser uses `fetch` → `Response.blob()` → `createImageBitmap()` → `ImageSource`/`Texture`. The renderer's idle waiter cannot advance while terrain, castle, or army art is pending.

The observer marked only the three army-plate geometry pages. It recorded loader cache/in-flight/unload-wait and per-asset completion, matched texture Blob and bitmap promise settlement, renderer/generation-specific attachment, ticker, and idle waiter stages into a bounded page-local buffer. `Response.blob` and `createImageBitmap` wrappers forwarded the original receiver and arguments and returned the **original promise**. Observational `then` side chains add microtasks and can affect scheduling; no extra fetch, decode, await, context read, or readiness wait was added. The other 13 browser pages had guards/method calls but no expanded diagnostic arrays or per-asset detail records. Each target buffer had zero dropped entries. The test attached it after the original poll outcome; later records must not be mislabeled as events that preceded the five-second deadline.

`castle-branch-mountain-v1.png` had no observed blob completion, bitmap start, `Assets.load` completion, or castle attachment on any of the three pages at their post-poll captures. For completed textures, median observed `Response.blob()` intervals were 693–801 ms across the pages, while median bitmap intervals were 61–72 ms. These concurrent per-asset intervals must not be summed or interpreted as pure CPU decode time. For example, the dense page's field-material blob call ran from browser monotonic 9,343.1 to 12,580.2 ms; its resource timing `responseEnd` was 12,561.8 ms, and its bitmap had not completed at capture. The body page's castle main-plain resource ended at 11,653.6 ms, blob completed at 11,655.4 ms, and bitmap completed at 11,740.2 ms. A resource timing entry exists only for a completed request; absence for a still-pending body read does not identify the network, server, or browser scheduler as the sole cause.

The measured proximal blocker is Pixi texture acquisition **before** terrain/castle all-settled and attachment. The current evidence narrows the delayed path to fetch/response-body delivery for several PNGs; it does not prove an intrinsic bitmap decoder or attachment defect, identify a server bottleneck, or justify restoring image workers. The prior [Blob transport controls](../blob-worker-transport-sim2/README.md) remain applicable. No texture, protected art, baseline, timeout, worker count, or product source was changed.

The run used `CI=1`, `VISUAL_GPU=1`, Chromium with the existing Linux Vulkan launch flags, 16 workers, the original 60-second case and 300-second global deadlines, and the unchanged five-second boot predicate. This does not establish same-page GL identity. Playwright/Node timestamps and browser `performance.timeOrigin`/`performance.now()` are separate clocks; this analysis uses same-browser stage intervals and does not subtract cross-process timestamps as a measured IPC delay.
